The heart of that machinery is a small shell script, and the difference between its first version and its second is the difference between believing a worker did something and knowing that it did.
So a reader of a v1 dispatch file could learn that a process finished, never that the worker produced the required answer.
That is the incident numbered INC-008 in the record: a pass that meant nothing, a false green on a test that could not distinguish the machine restating its instructions from the machine actually following them.
In other words, the test now fights the real output, not a cleaned-up copy of it.
That single change defuses INC-008 at the source, because there is no longer any echo of the brief in the stream the test inspects; the only text available is the worker's actual response.
It requires the needle to appear as the last non-empty line of the response, which is a much stricter condition than "somewhere in the transcript," and it is the condition that actually corresponds to the task being done.
The row is no longer written before the gate; it is written after the acceptance test runs, so a row in the file means the gate ran.
It is a single run, not a demonstration at scale, but it is a run on the real path with the real gate, and it is the run that the current file format and the current locking are built to represent.
Keeping the two categories separate means a reader of the record can tell, without reading the code, whether a given absence means a worker failed or a worker was never started.
